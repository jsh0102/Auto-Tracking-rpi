# 검출 모델 비교 — MobileNet-SSD vs YOLOv4-tiny

## 왜 재는가

저장소에 **모델 선택의 근거가 없었다.** 검출기는 첫 커밋(`1c70e4e 라즈베리파이 RTSP
송출`)에 MobileNet-SSD 로 들어왔고, 커밋 메시지·README·주석 어디에도 이유가 없다.
이전 STM32 프로젝트에서는 YOLOv4-tiny 를 썼으므로 오히려 되돌아간 셈인데, 그 이유도
기록되지 않았다. 이 문서가 그 빈칸을 채운다.

재는 것은 두 가지다.

```
① 추론 시간     한 장을 보는 데 몇 ms 인가      -> 그대로 "서보가 늦게 반응하는 시간"
② 박스 안정성   같은 장면에서 박스가 얼마나 튀나 -> 그대로 "가만히 있을 때의 떨림"
```

## ① 추론 시간

`camtracker` 와 **같은 OpenCV(4.5.1)** 로 빌드해 잰다. 파이썬 `cv2` 는 4.13.0 이라
그쪽으로 재면 실제와 다른 숫자가 나온다. 같은 입력, 워밍업 3회 뒤 15회 측정.

| 모델 (입력) | 평균 | 중앙 | 최소 | 최대 | fps |
| --- | --- | --- | --- | --- | --- |
| **MobileNet-SSD (300)** | **154.5ms** | 153.4 | 150.4 | 169.8 | 6.52 |
| YOLOv4-tiny (320) | 261.6ms | 260.1 | 254.0 | 268.2 | 3.84 |
| YOLOv4-tiny (416) | 447.5ms | 436.3 | 421.1 | 545.5 | 2.29 |

```
YOLOv4-tiny 320  =  SSD 의 1.7배 느림  (+107ms)
YOLOv4-tiny 416  =  SSD 의 2.8배 느림  (+283ms)
```

"연산량 5배" 라는 예상보다는 덜 느렸다. 그러나 이 프로젝트에서 중요한 것은 처리량이
아니라 **지연**이다. 검출 보간(KCF)이 있어 모델은 5프레임마다 한 번만 도는 반면,
지연은 매 검출마다 그대로 쌓인다.

```
지금        검출 지연 약 220ms   (지연 보상으로 대응 중)
YOLO 320    +107ms -> 약 330ms
YOLO 416    +283ms -> 약 500ms   추적 품질이 확실히 나빠지는 수준
```

## ② 박스 안정성

**같은 프레임 묶음**에 두 모델을 돌린다. 각각 따로 촬영하면 사람의 움직임이 매번
달라 모델 차이와 섞인다. 입력이 동일해야 차이가 모델 탓이 된다.

```
촬영   320x240, 10fps, 10초, 93장.  압축 없는 yuv420 (검출 경로와 같은 조건)
자세   정지.  따라서 박스가 움직인 것은 전부 모델의 잡음이다
임계값 conf 0.5 (config.json 과 동일), YOLO 는 NMS 0.4
```

| 모델 | 검출률 | 중심 이동 | 최대 | cx 표준편차 | 폭 변화 | conf |
| --- | --- | --- | --- | --- | --- | --- |
| **MobileNet-SSD 300** | 100% | **0.3px** | 0.7 | 0.4px | 0.6 | **1.00** |
| YOLOv4-tiny 320 | 100% | 0.4px | 1.1 | 0.4px | 1.4 | 0.91 |
| YOLOv4-tiny 416 | 100% | 0.4px | 1.2 | 0.3px | 0.9 | 0.92 |

**차이가 없다.** 0.4px 은 6.4px/도 환산으로 **0.06도**다. 두 모델 다 정지한 사람에
대해서는 잡음이라 부를 것이 없다.

이 측정은 별도의 소득이 있었다 — [jitter.md](jitter.md) 에 적었던 "DET 중심이
30.7px 튄다" 는 해석을 뒤집었다. 그 30.7px 은 잡음이 아니라 **1초 간격 샘플 사이에
사람이 실제로 걸어간 거리**였다. 같은 로그에서 정지 구간만 추리면 0.5px 이 나온다.

## 결론

```
속도      SSD 가 1.7배 빠르다        (153ms vs 260ms)
안정성    차이 없음                  (0.3px vs 0.4px, 둘 다 잡음 수준)
검출률    동일 100%
신뢰도    SSD 1.00  /  YOLO 0.91
```

**MobileNet-SSD 를 유지한다.** YOLOv4-tiny 로 바꿔 얻는 것이 이 조건에서는 없고,
지연만 1.7배가 된다.

### 이 결론이 닿지 않는 범위

측정 조건은 **실내 / 단일 인물 / 가까운 거리 / 밝은 조명 / 정지** 였다. YOLO 계열의
강점은 보통 그 반대쪽에서 나온다.

```
이 측정에 없는 것   가림, 원거리(작은 피사체), 저조도, 여러 명, 빠른 움직임
안 잰 것            정확도 자체(mAP). 공개 데이터셋 기준 성능은 측정하지 않았다
```

정확한 문장은 **"이 사용 조건에서는 SSD 가 낫다"** 까지다. 조건이 바뀌면 다시 재야
한다. 촬영한 프레임에는 사람이 찍혀 있어 저장소에 남기지 않았다 — 다시 재려면 아래
재현 방법대로 촬영부터 해야 한다.

## 재현 방법

```bash
# 가중치
curl -fL -o models/yolov4-tiny.cfg \
  https://raw.githubusercontent.com/AlexeyAB/darknet/master/cfg/yolov4-tiny.cfg
curl -fL -o models/yolov4-tiny.weights \
  https://github.com/AlexeyAB/darknet/releases/download/darknet_yolo_v4_pre/yolov4-tiny.weights

# 프레임 촬영 (압축 없음 — 검출 경로와 같은 조건)
libcamera-vid -n -t 10000 --width 320 --height 240 --framerate 10 \
  --codec yuv420 -o cap.yuv
ffmpeg -f rawvideo -pix_fmt yuv420p -s 320x240 -r 10 -i cap.yuv -vsync 0 frames/%04d.png
```

측정 코드는 OpenCV 4.5.1 로 빌드한다(`-I/usr/include/opencv4 -lopencv_dnn`).
추론 시간은 같은 blob 을 15회, 박스 안정성은 같은 프레임 묶음을 두 모델에 돌린 뒤
연속 프레임 사이의 중심 이동과 표준편차를 낸다.

## 겪은 것 — 촬영 전에 한 장을 먼저 봐야 한다

첫 시도에서 113장을 찍었는데 **검출률이 세 모델 모두 0%** 였다. 코드를 의심했지만
프레임을 열어 보니 흰 벽이었다. 카메라가 사람을 향하지 않았고, 도중에 **카메라가
쓰러졌다.** 틸트를 1150~2300 까지 훑어도 천장 조명과 벽만 나왔다.

그래서 절차를 바꿨다 — **본 촬영 전에 한 장을 찍어 사람이 잡히는지 확인하고, 안
잡히면 촬영을 시작하지 않는다.** 다시 세운 뒤에는 첫 각도에서 conf 0.999 로 잡혔다.

```
검출률 0% 를 보면 모델부터 의심하게 된다.  입력을 먼저 봐야 한다.
```
