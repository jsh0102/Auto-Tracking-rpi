# CPU 사용률 — pigpio vs 커널 모듈

## 무엇을 재는가

같은 일(서보 2채널을 중앙 1500us 로 고정)을 두 방식으로 시키고 시스템 전체 CPU 를
잰다. `/proc/stat` 의 누적 시간을 두 번 읽어 차이를 본다.

```
사용률 = (총 시간 증가분 - 유휴 시간 증가분) / 총 시간 증가분
```

**기준선을 빼야 한다.** Pi 는 가만히 둬도 CPU 를 쓴다. 그리고 기준선을 **처음과 끝
두 번** 잰다 — 같은 조건인데 값이 다르면 그만큼이 이 측정의 오차다. 그걸 모르면
작은 차이가 의미 있는지 판단할 수 없다.

`governor=performance` 로 고정해 세 조건의 클럭을 1800MHz 로 맞췄다.

재현: `sudo ./scripts/bench_pwm.sh` (조건당 60초, 약 4분 30초)

## 결과

| 조건 | CPU | 기준선 대비 | 판정 |
| --- | --- | --- | --- |
| 기준선 (처음) | 0.6% | — | |
| 기준선 (끝) | 0.5% | — | |
| **pigpio (DMA)** | 2.2% | **+1.7%p** | 유의미 |
| **커널 (hrtimer)** | 0.5% | **+0.0%p** | 오차범위 안 |

```
오차범위 +-0.1%p
```

**최소 17배 차이.** "최소" 인 이유는 커널 쪽이 0.1%p 보다 얼마나 작은지를 이
방법으로는 알 수 없기 때문이다.

4코어 기준 1.7%p = 1코어의 약 6.8% 를 pigpiod 가 상시 점유한다.

## 예상과 달랐던 점

작업 전 가설은 **"커널 쪽이 더 높을 것"** 이었다. 근거는 인터럽트 횟수였다.

```
pigpio   DMA 가 파형을 만든다. CPU 가 관여하지 않는다
커널     한 펄스당 인터럽트 2번 x 50Hz x 2채널 = 초당 200회
```

틀렸다. 이유는 **한 번의 비용**에 있었다.

```
콜백 1회      약 2~5us (핀 하나 뒤집고 다음 알람 예약)
초당 200회    400~1000us = 1초의 0.1%  -> 측정 한계 아래
```

그리고 pigpio 의 1.7%p 는 **펄스 생성 비용이 아니라 데몬이 상주하는 비용**이다
(소켓 대기, GPIO 샘플링, DMA 버퍼 관리). 파형 생성은 정말로 공짜였지만, 그걸
지시하는 프로세스가 24시간 떠 있어야 한다.

**"누가 펄스를 만드느냐" 가 아니라 "데몬이 있느냐" 가 CPU 를 결정했다.**

## 곁가지로 확인된 것

첫 측정(조건당 30초)에서 커널이 기준선보다 *낮게* 나왔다.

```
기준선  0.9%
커널    0.6%     <- 펄스를 만드는데 CPU 가 줄어들 수는 없다
```

측정 잡음이었다. 기준선을 두 번 재도록 고쳐 오차범위를 ±0.1%p 로 확인하고 나서야
"커널 쪽은 이 측정으로 잡히지 않는다" 고 말할 수 있게 됐다.
**오차범위를 모르면 결과를 해석할 수 없다.**
